# 预览发行流程

当前发行目标为 Windows x64。版本字段保存在 `package.json`、`src-tauri/Cargo.toml` 与 `src-tauri/tauri.conf.json`，发版时同步编辑它们，不生成另一份版本文件。

## 公开基线

合入前审阅工作树差异、跟踪文件、分支和标签；根目录许可证、第三方说明、README 和安装文档必须与实际发行内容一致。`test/`、依赖、数据根、参考 checkout 与构建产物保留在忽略规则中。可用临时目录从待发布提交作干净克隆，按 README 安装依赖、构建并核对输出；本机原有 `node_modules` 或 `artifacts` 不能替代此检查。

## 自动检查与上游更新

`check.yml` 在 Windows 上安装锁定依赖，检查 TypeScript 和 Rust 格式，再重建锁定 OMP、执行不调用模型的协议烟测与桌面编译检查。

`upstream-runtime.yml` 每 12 小时检查一次最新上游 Release，也可手动运行。只读任务克隆并构建候选，验证后上传 NSIS 安装器、SHA-256 校验和及生成文件差异。独立的写入任务只把生成协议、客户端与版本锁提出 PR；它不构建或执行上游代码。需要在仓库 Actions 设置中允许 GitHub Actions 创建 PR。维护者在合并前复核补丁兼容性与安装器行为；失败候选不更新主分支。

Bun 1.4.4 是当前已验证的发行工具版本；锁定 OMP、原生 addon 与生成 wire 的原因是协议和 ABI 兼容。更新责任人为仓库维护者，升级时同步重新验证这些输入。

## 创建 Windows 预览草稿

1. 在待发布提交上创建 `vX.Y.Z-preview.N` 标签，`X.Y.Z` 与三处桌面版本一致。
2. 推送该标签后，在 Actions 手动运行“Windows 预览发行”，填写已有标签。
3. 流程在只读任务中重新构建运行时与安装器，生成 `SHA256SUMS` 和许可附件；另一个只具发行写权限的任务创建标记为 Pre-release 的草稿。
4. 维护者检查附件哈希、实际安装、首次启动、升级与数据保留，完善版本说明后发布草稿。

同一草稿可重复运行来更新附件；已经公开的发行不会被流程覆盖。当前安装器未签名，发行说明必须保留该事实与 WebView2 要求。后续启用签名时同步修改安装器验证与发行说明。
