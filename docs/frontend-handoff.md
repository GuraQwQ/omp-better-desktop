# Frontend integration handoff

Frontend owns `src/` except `src/generated/`, and `test/session-state.test.ts`. The initial UI is built and production TypeScript/Vite compilation passes. It includes project/session navigation, streaming transcript virtualization, standard OMP UI requests, installation/import/takeover settings, model picker, command palette, usage/files/diff/tasks/agents inspector, and lazy xterm handoff.

The frontend now targets `desktop_settings` with `{operation:'list'|'set'|'unset',key?,value?}`. Please keep this contract in the runtime patch. Settings list can return an entries array or object keyed by setting path. Standard entries should carry `path` or `id`, `type`, `value`, `ui.label`, `ui.description`, and `enumValues`.

The user accepted the exact layout in the implementation plan. The UI uses the code-led path without another design interview. Source implementation is bilingual and uses system theme. Browser preview is an empty real shell, not a populated mock.

Verification so far: production build passes; 3 session-event tests pass (delta/final replacement, settled vs yielded, background question cancellation). Browser checks passed 1440x900 and 1000x700 layout, language/theme switching and prompt shortcuts. Final browser validation and detector are still in progress. QA images are under `.impeccable/review/` and ignored.

Root action needed: check runtime settings command, CLI catalog routing, and use `docs/desktop-contract.md` event shapes. `runtime.install` selects a directory containing `runtime-manifest.json`. Main UI needs to retain session ids after CLI/terminal handoff and attach to saved path.

Potential missing first-run usability: Providers settings currently require a live session. Frontend will open a session when entering settings with a selected project and runtime; root backend must allow authenticated-provider discovery without sending a model request.

Update: schema normalized to key/options. Providers login uses providerId. OAuth opens native system.open_url. Settings auto-opens a selected project session (without model request) and presents pending auth questions above settings. Added Close conversation so runtime/data operations can release idle sessions. Command palette now dispatches RPC entries through a form generated from the upstream schema and routes mapped panels. It routes unsupported built-in TUI commands to the embedded terminal rather than mis-sending them to the model; this preserves functionality but does NOT satisfy full native GUI coverage for those commands. Root/integration must close those native parity gaps or report them explicitly.

Follow-up fixes implemented: state refresh after prompt_result/session_settled/config_update/session_info_update; title reads event.title; set_editor_text is scoped to the source session with saved drafts; secret inputs use password controls; new/fresh/clear use new_session; quit/exit close; restart closes/reopens; copy reads last assistant text; open opens file panel; btw/goal/guided-goal/queue route to schema-generated RPC forms; queue supports promotion; tree displays branch/fork controls. Plan/vibe/loop route to live settings filtered by domain. IMPORTANT: plan.enabled only enables the capability and does not enter session plan mode; vibe mode has no discovered settings domain. Dedicated RPC mode activation still needs an engine patch; do not claim these modes are native-complete.
